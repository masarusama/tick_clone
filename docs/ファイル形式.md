# メモのファイル形式（自分で触れる、ただのファイル）

tick_clone のメモは、**1件 = 1つの Markdown ファイル**です。アプリを使わなくても、エディタで開けて、`grep` で探せて、スクリプトで読み書きできます。**正本は、このファイル**です。画面の検索や一覧を速くするための索引（SQLite の `index.db`）は、消しても、ファイルから作り直されます。

## 置き場所

```
data/                       ← 環境変数 TICK_DATA で場所を変えられる（それ自体が git のリポジトリ）
├─ notes/2026/10/20261024-101530-a3f9.md    メモ（年/月/ID.md）
├─ trash/20261001-120000-0b1c.md            ゴミ箱（平らに置く。消した日時が trashed: に入る）
├─ attachments/                             画像・PDF などの添付（git の管理外）
├─ settings.json                            リストの並び順・フィルター・自動振り分け・タグの色
├─ push/                                    通知の鍵と登録（秘密。git・バックアップの対象外）
└─ index.db                                 索引（消してよい。起動時に作り直される）
```

## 1つのメモ

```markdown
---
id: 20261024-101530-a3f9
created: 2026-10-24T10:15:30+09:00
updated: 2026-10-24T10:20:05+09:00
kind: task
list: 仕事/企画
due: 2026-10-29
allday: yes
priority: 5
---
企画書を提出する
- [ ] 構成を決める
- [ ] 図を作る

#仕事
```

- 先頭の `---` と `---` の間が**属性**（1行に、`キー: 値`）。その下が**本文**（Markdown）。
- **1行目が題名**です（題名の欄は、別にありません）。
- **タグは、本文の `#タグ`** から読み取ります（属性には書きません。`#本/小説` のように `/` で階層になります）。
- **ファイル名は `ID.md`**。`id:` と同じにしてください（形は `年月日-時分秒-16進4桁`）。

## 属性の一覧

| キー | 値 | 意味 |
|---|---|---|
| `id` | `20261024-101530-a3f9` | メモの ID（ファイル名と同じ） |
| `created` | `2026-10-24T10:15:30+09:00` | 作った日時 |
| `updated` | 同上 | 更新した日時（本文などを変えたとき。並べ替えだけでは変わらない） |
| `kind` | `task` / `note` | タスク（完了できる）/ ノート（読み物・資料。完了しない）。無いときは、`status:` か `due:` があればタスク、無ければノート |
| `status` | `open` / `done` / `abandoned` | 未完了 / 完了 / 中止（キャンセル）。無ければ未完了として扱う |
| `completed` | `2026-10-24T18:00` | 完了した日時（`status: done` のとき）。**実績の記録** |
| `cancelled` | `2026-10-24T18:00` | 中止にした日時（`status: abandoned` のとき）。実績には数えない |
| `due` | `2026-10-29` または `2026-10-29T15:00` | 期日（終日 / 時刻つき） |
| `allday` | `yes` / `no` | 終日かどうか |
| `start` | `2026-10-27` | 複数日の予定の、開始日（`due` が終わりの日） |
| `event` | `1` または `17:00` | 予定の印（過ぎても期限切れにならない）。`17:00` は、予定の終わりの時刻 |
| `repeat` | `FREQ=WEEKLY;BYDAY=FR` | 繰り返し（`FREQ` `INTERVAL` `BYDAY` `BYMONTHDAY` `BYMONTH` `UNTIL`） |
| `last_done` / `last_cancelled` | 日時 | 繰り返しの、直前の回を、完了・中止した日時 |
| `reminder` | `-PT10M / PT0S` または `none` | 通知する時刻（期日の何分前か。ISO 8601 の長さを ` / ` で並べる）。無ければ既定（終日は当日の朝9:00、時刻つきは期日の時刻） |
| `priority` | `1` / `3` / `5` | 優先度（低 / 中 / 高。TickTick と同じ値） |
| `pinned` | `2026-10-24T10:00` | ピン留めした日時 |
| `list` | `仕事/企画` | リスト（1つだけ。`フォルダ/リスト` の2階層まで。無ければ受信箱） |
| `sort` | `-123.5` | 手動の並べ替えの位置（小さいほど上） |
| `source` | `ticktick` | 取り込み元の印 |
| `trashed` | 日時 | ゴミ箱へ移した日時（`trash/` の中だけ） |

知らないキーは、そのまま残されます（消えません）。日時は、**日本時間（+09:00）** で記録されます。

## 外から触るときの注意

- **サーバーは、起動時に、ファイルを読み直します**（変更があったファイルだけ）。動いている最中の外からの変更は、**再起動するまで、画面に出ません**。ふつうは、サーバーを止めて編集するか、編集のあとに再起動してください。再起動すると、端末（スマホなど）にも、変更が同期されます。
- **アプリで、同じメモを開いているとき**に、ファイルを直接書き換えると、あとから保存した側が勝ち、負けた側は「競合」として別のメモに残ります（内容は消えません）。
- **git の履歴**: アプリでの変更は、数秒後に、`data/` の git に記録されます。外から直した分は、**次の記録に、まとめて含まれます**（すぐ残したいときは `git -C data commit -am "メモ"`）。
- **大量に作る・直すスクリプト**を書くときは、メモ1件ずつ、`id` と `created` を決めて、`notes/年/月/` に書き出し、最後にサーバーを再起動すれば、取り込まれます（`tools/import_ticktick.py` と `tools/seed_demo.py` が、実例です）。

## 外のツールと一緒に使う

- **検索**: `grep -r "締切" data/notes`、`ripgrep`、エディタの全文検索。
- **同期・バックアップ**: `data/` を、好きな方法で（`tools/backup.py`、rsync、別の git リモートなど）。
- **ほかのアプリで読む**: ただの Markdown + 属性なので、Obsidian などでも、ある程度は読めます。
- **自動化・AI**: 完了した日時（`completed:`）や、書いた日時（`created:`）から、日誌や実績の集計を作る、といった使い方ができます。
